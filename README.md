# RDV Маркет — пять новых блоков

Локальная адаптивная верстка по [Figma](https://www.figma.com/design/qIMeZ9epTSp30QeXZqfItB/?node-id=956-1627) и [ТЗ](https://docs.google.com/document/d/1KBORlwQXju2VSY33jP1MWrPpVyHzgFiJGdUDSkytQg4/edit). HTML, CSS и JavaScript без фреймворка и внешних зависимостей. Все изображения и шрифты хранятся локально.

## Запуск

Нужен Node.js 18+. Установка npm-пакетов не требуется.

```sh
npm run dev
```

Открыть http://localhost:4173. Для другого порта: `PORT=4174 npm run dev`.

```sh
npm run build
npm run preview
```

Сборка записывается в `dist/`. В `dist/index.html` уже присутствует готовая HTML-разметка: текст доступен до загрузки JS. В `dist/blocks/` — отдельные фрагменты пяти блоков, заголовка и статистики без диаграммы. `preview` нужно запускать после остановки `dev` либо с другим `PORT`.

## Состав

1. Статичный первый экран с четырьмя иллюстрированными карточками.
2. Видеоблок с превью, заголовком и стрелкой.
3. Шахматная сетка из шести карточек, два варианта наведения.
4. Архитектура RDV Маркет: диаграмма и статистика в четырех карточках.
5. Пять вкладок с иллюстрациями и переключением по клику.

Шапка и футер заимствованы с действующего сайта вместе с исходными стилями. Мобильные переопределения шапки в стилях превью удалены; исходная фиксированная шапка сохраняется, а контент резервирует ее фактическую высоту. Они включены только в локальное окружение для проверки совместимости. Остальные секции длинного макета не включены. Контейнер — до 1240 px с боковыми отступами 20 px. На телефонах до 767 px используются вертикальные карточки, компактные иконки, текст над видео и аккордеон вместо вкладок. На планшетах 768–1023 px карточки и статистика перестраиваются в две колонки. Минимальная ширина локального превью — 320 px.

## Настройки

Контент задается в `scripts/config.js`; разметка — в `scripts/blocks.js`; стили блоков — в `styles/blocks.css`. После изменения конфигурации обновить страницу; для выдачи файлов интегратору повторить `npm run build`.

| Настройка | Назначение |
| --- | --- |
| `hero.background` | URL фона первого экрана; `null` убирает фон |
| `hero.brand` | Отдельные логотипы и стрелка; `null` позволяет использовать `hero.image` |
| `hero.image` / `imageAlt` | Картинка над заголовком, естественный размер с ограничением шириной контейнера |
| `hero.buttons` | Одна кнопка по центру; для двух кнопок промежуток находится точно по центру |
| `hero.showCards` | Показывать или скрывать карточки |
| `hero.cards[].mobileIcon` | Мобильная иконка: `{src}` или `{kind, layers}` для композиции из нескольких SVG |
| `hero.cards` | От двух до четырех карточек; изображение отделено от текста и выводится целиком |
| `video.type` | `rutube`, `file` или `image` |
| `video.src` | Для Rutube — `https://rutube.ru/play/embed/ID`; для файла — путь к MP4/WebM; для картинки — ее URL |
| `video.poster` | Превью видео |
| `video.image` | Дополнительная картинка под текстом, можно убрать |
| `video.captions` | Необязательный путь к русским субтитрам VTT |
| `methodologyTitle` / `methodologyAccent` | Отдельный заголовок над сеткой; пустое значение убирает его |
| `chess.hover` | `results` — синий фон с показателями; `simple` — белый фон и бирюзовая стрелка |
| `chess.cards[].hover` | Необязательное переопределение ховера конкретной карточки |
| `chess.cards[].background` | Картинка фоном всей карточки, заменяет исходную композицию |
| `chess.cards[].mobileIcon` | Мобильная иконка; на телефоне заменяет крупную декоративную композицию |
| `chess.cards[].icon` | Иконка справа снизу, отображается только в маленьких карточках |
| `chess.cards[].results` | Массив пар `[число, подпись]`, 2–4 показателя с учетом размера карточки |
| `architecture.title` / `image` / `imageAlt` | Заголовок, URL диаграммы и ее текстовое описание; исходная диаграмма — WebP 2476 × 884 px для Retina |
| `stats` | Три или четыре карточки, автоматически делят ширину |
| `workspace.description` | Описание раздела; пустая строка скрывает его |
| `workspace.tabs[].background` | Фон всей правой половины вкладки |
| `workspace.tabs[].iconName` | Векторная иконка: cloud, experience, launch, solutions, support; цвет через currentColor |
| `workspace.tabs[].iconHasBackground` | `true` для загруженной единой картинки 36×36 с собственным фоном |
| `workspace.tabs[].items` | Массив пунктов списка |
| `workspace.tabs[].text` | Обычный текст вместо списка, если `items` отсутствует |
| `workspace.tabs[].showMore` / `href` | Показывать ссылку «Подробнее» и ее адрес |

Контент всех блоков общий для мобильной и десктопной версии: заголовки, описания и подписи задаются один раз. Адаптивные стили меняют оформление и расположение элементов. Переносы в текстах обозначаются `\n`. Строки экранируются; произвольный HTML из конфигурации не исполняется. Текстовые контейнеры растут по содержимому: фиксированных высот, обрезки текста и ограничения числа строк нет. Длинные слова переносятся. Оба состояния шахматки находятся в одной ячейке CSS Grid и участвуют в расчете высоты, поэтому наведение не меняет размеры карточки. При увеличении текста блоки становятся выше — исходная высота макета не фиксируется. Для коммерческих показателей используется текст макета, без самостоятельной проверки этих утверждений.

## Перенос в Битрикс

Текущий сайт использует Битрикс. Этот проект готовит фронтенд; регистрации блоков в админке, загрузки файлов через CMS и обработки заявок здесь нет.

1. Скопировать `assets/`, `styles/blocks.css`, `scripts/blocks.js`, `scripts/tab-icons.js` и `scripts/init.js`, сохранив взаимное расположение каталогов. При другом размещении скорректировать пути в HTML, CSS и функции `asset()`.
2. Подключить `styles/blocks.css` один раз и вставить нужные фрагменты `dist/blocks/*.html` в любое место шаблона. Каждая секция — самостоятельный БЭМ-блок: `rdv-hero`, `rdv-video`, `rdv-chess`, `rdv-architecture`, `rdv-stats`, `rdv-workspace`. Общий контейнер не нужен. Элементы имеют классы вида `rdv-workspace__tab`, модификаторы — `rdv-chess__card--reports`.
3. Подключить `<script type="module" src="/путь/scripts/init.js"></script>`. Атрибуты `data-rdv-block` и `data-rdv-video` используются только JavaScript; CSS работает через БЭМ-классы. Параметры плеера хранятся в HTML самой секции, глобальный `config.js` при статическом подключении не нужен.
4. Для секций, добавленных после загрузки страницы, вызвать экспортируемую функцию `bindInteractions(section)` из `scripts/init.js`. Можно передать документ целиком; повторная инициализация не добавляет обработчики повторно. Возвращаемая функция очищает обработчики. Несколько экземпляров вкладок и видео работают независимо; связанные ARIA ID назначаются каждому экземпляру.
5. Перенести данные `config.js` в поля CMS. Генераторы в `blocks.js` показывают структуру HTML. Заголовок шахматки находится в отдельном фрагменте `heading.html`. `architecture.html` включает диаграмму и статистику; `stats.html` оставлен для отдельного использования карточек.
6. CTA ведут к существующей форме `https://rdv-market.ru/#formEvent`. При интеграции подключить обработчик действующей формы и нужные атрибуты типа заявки. Отправка заявок локально не имитируется.
7. `index.html`, `styles/demo.css`, `styles/site-shell.css`, `scripts/site-shell.js` и заимствованные шапка/футер служат только локальному превью. Их не нужно вставлять поверх уже существующей шапки и футера продакшена. Новые стили не задают глобальные правила для `html`, `body`, `button` или других элементов сайта.

Rutube создается только при открытии видео. Закрытие кнопкой, Escape или кликом по затемнению удаляет плеер и прекращает воспроизведение. Вкладки поддерживают стрелки вверх/вниз, Home и End. На телефоне эти клавиши перемещают фокус между заголовками; Enter или пробел раскрывают пункт. Повторный клик сворачивает открытый пункт, одновременно раскрыт максимум один. Раскрытие и закрытие анимируются через `grid-template-rows: 0fr → 1fr` за 300 мс; свернутый контент исключен из фокуса через `inert`. При изменении ширины экрана сохраняется выбранный пункт; колесо мыши не меняет вкладку. Анимации отключаются при `prefers-reduced-motion`.

## Независимость от контента

- Иллюстрации карточек, постер и изображение видеоблока сохраняют пропорции и выводятся целиком. Текст и изображения занимают отдельные места в потоке.
- Иконки ограничены размером своего места и используют `object-fit: contain`. Иконки вкладок — inline SVG с currentColor; общий фон задается CSS, активное состояние одинаково для всех вкладок.
- `hero.background`, `chess.cards[].background` и `workspace.tabs[].background` используют единые правила CSS-фона (`cover`, без повторения). Фон может обрезаться по краям при отличии пропорций; это фон, а не контентная иллюстрация. Читаемость текста поверх выбранного фона зависит от самой картинки.
- Декоративные композиции подключены как WebP `hero-background@2x.webp`, `chess-*@2x.webp`, `workspace-*@2x.webp`; иллюстрации первых карточек экспортированы из Figma в 4× и переведены в WebP. Координат отдельных декоративных слоев в CSS компонентов нет. Для замены достаточно поменять URL.
- Проверка после изменений: 41 сценарий в браузере, включая длинные тексты, длинные слова без пробелов, изображения 292×300, 1200×180 и 180×600. Результаты: `output/playwright/content-qa-results.txt`. Воспроизведение локального WebM проверено на тестовом файле; Rutube — создание iframe и закрытие плеера.

## Проверка независимых секций

После перехода на БЭМ проверены две копии вкладок и видеоблока, повторная инициализация, уникальность ARIA ID и длинный текст. Сравнение 333 элементов локально заимствованных шапки и футера с включенным и выключенным `blocks.css` не обнаружило изменений проверенных свойств. Результат: `output/playwright/bem-qa-results.txt`. Это проверка данного шаблона, а не гарантия совместимости с любым сторонним CSS.
